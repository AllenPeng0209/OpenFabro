# Source-bound route length tuning

Implement the documented AI length/matching workflow on existing native copper. Support exact
millimeter targets, reference-net matching and delay targets only with explicit layer/via models.
Preserve logical pins, board, unrelated copper/zones, existing vias and stable unaffected identities.
Use real line/arc primitives for trombone, accordion and sawtooth patterns, configurable pitch/radius
and a bounded deterministic search for free placement. Declared paired tuning must keep both nets
together; independent matching and pair skew must not be represented as measured signal integrity.

Report the measurement convention and unsupported/ambiguous topology rather than inventing lengths.
Preview and application share one engine, reject conflicting targets and verify actual native pin
membership, tuned lengths and DRC before any accepted save. Snapshot version, semantic source and
PCB digest throughout asynchronous preparation; Agent preview is read-only and Chat cannot mutate.
UI changes, cancellation, account/project/native replacement and concurrent saves invalidate drafts.
Use the existing whole-spec history for one complete tuning transaction and exact Undo/Redo.

The official workflow is AI driven. New local inspection/review controls are functional integration,
not proof of an unobserved Flux tuning dialog's pixels. Advanced route/outline/topology, physical SI,
clean installation and touch acceptance remain explicitly tracked until verified.
