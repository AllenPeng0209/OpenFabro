# Reviewed Part Type interface presets

Manual bus editing already preserves native connectivity and copper, but configuring every pin
individually is slow. A Part Type can provide a deterministic, inspectable starting point.

Recognize the native symbol's electrical pin names for all13 supported interface Part Types.
Keep display aliases and net names out of matching. Report unmatched pins, incomplete pairs,
conflicting duplicate roles, selected-width violations and P/N shorts. Repeated USB-C contacts
must have a proven common net on each side. Keep power pins unchanged.

Generate a private candidate and native pin proof before applying. Part Type, per-pin identities
and declared targets commit in one normal design operation with Undo/Redo. An unresolved setup
returns no applicable spec to either the editor or Agent. Existing values require explicit Keep or
Replace; kept pair targets are coherent on both legs and unrelated pin delays/timing remain intact.

The dialog retains project/load/view/selection/account ownership, request order, settings revision
and saved-design identity. Late openers and previews cannot replace a newer dialog or survive
navigation, selection changes or a peer save.

Nominal targets are editable assumptions, not full protocol specifications. No tolerance or skew
is generated without input. See the [reference and engineering sources](../reference/flux-interface-presets.md).
